# 功能详解

本文保留当前实现的匹配规则、投递状态和平台差异。安装方式以根目录 README 为准。

#### AI 匹配评分

- 总分由后端固定计算：**任职要求 80% + 工作职责 15% + 求职偏好 5%**，语义推荐和投递前评分共用此规则；评分理由显示各分项和权重。
- 优先核对任职要求中的必备技能、学历、经验等，认可等价能力与可迁移项目经历。“优先”“加分项”不作为硬性缺项扣分；“或/之一”按任选条件判断。未提及的信息标为待确认，不虚构为已满足或确定缺失。
- 岗位名称、公司行业及职责中的前沿技术不会自行变成硬门槛；明确要求的必备经验仍正常扣分。黑名单、薪资等既有硬过滤和最低分阈值不变。
- 岗位画像未填个人介绍时使用全局 AI 个人画像；搜索关键词仅代表求职偏好，不当作技能证明。全局打招呼语模板不参与评分。
- 「告诉模型你想投递什么岗位」随当前画像保存，并同步到平台回退配置。启用「AI 岗位匹配门禁」后，投递前评分会自动结合这段意向描述与已填写的技术栈、项目经历，评估工作方向是否符合偏好（计入求职偏好分），无需单独点击找岗位。描述不作为已掌握技能的证据；留空时保持原有评分逻辑。
- 配置顺序为「发送模式 → 告诉模型你想投递什么岗位 → 岗位画像」，修改描述后先点击右上角「保存配置」。保留 Ctrl / Command + Enter 对已抓取候选岗位重新评分排序的快捷操作。
- AI 超时、请求失败或未返回有效的三个分项时，**不再使用本地关键词匹配**。自动投递会停在当前岗位，每次失败后等待 **30 秒**再请求 AI，没有重试次数上限；获得有效评分后才继续原有筛选和投递。失败期间不保存替代分数、不跳过当前岗位、不点击沟通或发送，可点击停止；BOSS 登录、验证、会话变化等安全检查仍有效。每次 AI 请求保留原有超时，正在请求时停止可能需要等该次请求返回或超时。手动语义推荐接口失败时明确报 AI 不可用，不返回本地替代评分；已有历史评分不会被自动清除。
- 修改规则不会直接改写历史分数。重启后端后，重新运行语义推荐或在后续抓取中重新评分，才会保存新分数。

#### BOSS 发送模式与安全暂停

- **确认并发送（默认）**：先生成持久化草稿，不点击“立即沟通”或发送消息。在“待确认投递”中逐条查看岗位、编辑招呼语，再明确确认或跳过。
- **自动投递**：保存模式后，新产生的岗位可按配置自动执行。批量任务按城市和关键词完成一轮后自动开始下一轮，零发送的一轮也继续，直到手动停止、退出自动模式或出现需要人工处理的异常。每轮重新读取已保存的配置，重新分配每个城市/关键词的检查额度；历史已投递、已有草稿和 `UNKNOWN` 不会重发。循环期间保持同一个任务和停止开关，不并发启动另一批。切换模式不会自动发送此前的待确认草稿；单岗与批量共用相同状态和节流规则。确认模式仍只准备一轮，释放任务后才能逐条确认。
- 网页保存配置时将投递间隔设为 **60-120 秒随机整数（含端点）**，未配置时也默认这一范围。每次先点击“立即沟通”，进入对话并填好招呼语，再抽取一次间隔，**在对话页面完整等待后才点击发送，第一条也等待**；浏览、评分耗时不抵扣这段等待。上传图片不再重复等待，等待期间可停止任务；输入框内容变化或登录/验证异常时不点击发送。`wait_time` 为下限，`wait_time_max` 为上限；旧配置缺少上限时取 120 秒或已有下限中的较大值。单岗投递和确认发送的前端请求超时为 240 秒。每轮每个城市/关键词最多新检查 **100 个岗位**（5 个关键词、1 个城市每轮最多 500 个），重复和已有投递记录不占额度，不把其他关键词未用完的额度追加到当前关键词。列表预加载最多滚动 **20 轮**，达到 100 个已加载岗位或连续 **2 轮**没有新增即结束加载；实际可用新岗位不足 100 个时按实际数量处理，不虚报为已检查 100 个。自动批量循环不再受本地 30 分钟总时长截止影响，单岗和确认模式保留原预算；浏览、导航和回执等待的超时、节流及安全检查不变。明确显示“没有找到相关职位”的空结果页会跳过当前关键词并继续，不会误报登录异常；没有列表也没有明确空结果提示的页面仍按异常暂停。每轮结束报告轮次、确认发送、待核对、薪资排除、AI未通过等计数，并提示继续下一轮，不再把一轮结束当作整个任务结束。
- **浏览另有限速**：搜索导航、主动滚动、详情点击和发送前打开详情页共用至少 **15 秒**间隔，不占用或替代随机投递间隔。跳过岗位、AI 评分失败或不发送消息，也不能绕开浏览限速。每小时和每日主动浏览次数限制默认关闭（`max-browse-per-hour` 与 `max-browse-per-day` 均为 `0`，表示不限）；同一搜索的额外冷却也已关闭（`search-cooldown-minutes: 0`），可重新启动搜索，不再等待 15 分钟。启动时仅清除旧版本因这一已关闭的搜索规则留下的暂停，验证码、平台限制和发送结果不确定的暂停仍需人工处理。浏览记录按本地安装累计，存入 SQLite，停止任务、重新登录和重启程序不会清空记录。如将次数预算或搜索冷却设为正数，则重新启用对应限制。这是本地主动动作控制，不是网页后台 HTTP 请求总数，也不是平台公布的安全阈值。
- 请求详情前先跳过本轮重复、已确认投递或当前会话已有草稿的岗位（含 `UNKNOWN`）；其他岗位优先复用 **6 小时**内的已验证详情缓存，仍按当前画像重新评分。缓存只保存岗位必要字段，不保存 API token、Cookie 或整份响应。预算与缓存参数位于 `../src/main/resources/application.yaml` 的 `boss.safety` 下。
- 停止后显示 `STOPPING`，只有浏览器任务实际退出才释放任务槽；卡死时不要反复启动新任务。
- 验证码、登录失效、访问限制、HTTP 401/403/405/429，以及浏览器、网络或状态保存异常仍会暂停。“访问受限 / 抱歉，您暂时无法访问此页面”有独立识别，恢复前也会检查；不会把 AI 服务的 429 当作 BOSS 限制。限制日志记录动作、去掉查询参数的路径、HTTP 状态和业务码，不打印响应正文。导航失败不自动刷新重试。请按原因处理后，勾选人工核对并点击恢复；服务器要求的 `Retry-After` 或本地冷却未结束前不能恢复。
- **自动投递不会因单条消息回执识别失败而停止整批**：该岗位记为 `UNKNOWN`（待核对），不重复发送，按投递间隔继续处理其他岗位。真实平台限制优先于这一规则；结束时分别统计已确认发送和待核对数量。
- `UNKNOWN` 表示可能已经发生外部操作，需要事后在官方界面核对，但不是账号受限的证据。重启不会重放 `IN_FLIGHT` 操作；若重启打断了发送过程，仍需先核对中断结果。`SENT` 只指招呼语获得明确 UI 确认，不代表附件已送达。
- 发送确认兼容“送达”和“已送达”，仍要求本次新增、自己发出且有可识别身份的消息。最长等待 15 秒；超时会输出仅含计数的诊断（例如 `notOutgoing`、`missingIdentity`、`missingReceipt`），不打印聊天内容。消息已出现但仍标为 `UNKNOWN` 时，不会假记成成功，也不会仅因此暂停其他岗位；没有账号级暂停时会关闭该详情标签，避免批次中不断累积页面。
- 草稿绑定创建时的登录会话；退出登录或凭证轮换后可能需要重新生成草稿，不能跨会话直接发送。
- 图片简历只在招呼语确认后单次尝试上传；附件状态需在官方界面另行核对。没有可靠的消息身份或成功状态时，程序保持未知，而不是把输入框清空当成功。
- 升级会自动新增 `delivery_mode`、草稿表、暂停记录表、`boss_browse_event` 和 `boss_detail_cache`，不要覆盖现有数据库或删除暂停记录。升级不会解除已经发生的平台限制。后端默认仅监听 `127.0.0.1:9527`，Cookie 接口不返回凭证原值；不再保存、读取或导入历史 Cookie 用于登录。

上述稳健性措施不构成平台授权。确认模式也仍由第三方程序执行最终点击；如未获平台许可，应仅使用本地整理、匹配与草拟功能，在官方界面自行发送。请遵守 [BOSS 用户协议](https://about.zhipin.com/agreement?id=registerprotocol)，不要规避验证、限制或额度。

本地回归验证：`gradlew.bat test -x buildFrontend -x processResources`；前端状态测试：在 `front/` 执行 `npm run test:boss-delivery`。消息回执测试仅使用隔离的空白 Chrome 页面并阻止全部网页请求，不会使用真实账号。

### 猎聘、51job、智联的确认与自动投递

三个平台共用投递队列和执行状态管理，但各自保存发送模式、暂停记录和浏览额度。管理页面的“发送模式与待确认投递”区域支持：

- **逐条确认（默认）**：保存搜索条件，点击“开始任务”只生成待确认列表；核对公司、岗位后点击“确认投递”，在确认框中执行该岗位的一次操作。
- **自动投递**：选择并点击“保存发送模式”，再启动任务；只处理本次新准备的岗位。切换模式不会发送之前遗留的待确认记录，运行中的任务按启动时保存的模式执行。
- 猎聘使用平台“聊一聊”的默认沟通方式；51job、智联使用平台已保存的默认简历。这里没有新增 BOSS 专用的 AI 招呼语、图片简历发送功能，也不会自动申请弹窗中的相似岗位。
- 按平台域名、岗位 ID、标题和公司重新核对目标，不以接口数组位置对应页面卡片。51job 的批量按钮只在核实**仅当前一个岗位被选中**后点击，不再整页批量投递。
- 只有新的明确成功提示才记录为 `SENT`；智联的新弹窗还需绑定本次操作的来源页面。点击成功不等于投递成功；回执不明、异常或重启中断记录为 `UNKNOWN`，不自动重发，重新登录/凭证轮换也不会解除已有尝试的去重。
- 确认草稿绑定创建时的登录会话，不能跨会话直接发送。旧的未发送草稿可忽略后重新准备；已尝试的岗位默认按平台跨会话保守去重。
- 每次最多检查 20 个岗位、最多 5 个关键词且每个只读取首页，单次时长预算 30 分钟。发送至少间隔 120 秒，主动浏览至少间隔 15 秒；每平台滚动一小时 60 次、24 小时 150 次浏览，任务采集同一搜索间隔 15 分钟（逐条确认重新打开列表按浏览间隔计）。限速记录持久化，重启不会清零；这些限制不能保证平台不再限制访问。
- 遇到验证码、访问限制、接口 401/403/405/429、投递额度提示或状态保存异常时暂停，遵守 `Retry-After`。人工处理并勾选确认后才可恢复；恢复不会自动启动，也不会重发未知记录。停止须等待实际浏览器工作退出，退出登录也不能抢占仍在运行的任务。
- 队列不会额外轮询招聘网站；点击“刷新队列”读取本地结果。升级自动新增 `platform_delivery_*` 表，保留原有数据库及投递统计。修改后需重启后端；前端源码变更需重新构建。

回归测试使用临时 SQLite、模拟接口及隔离 Chrome 中的本地页面，不连接真实招聘账号；尚未对三个平台当前线上页面完成实投验证。页面结构不匹配时会暂停而非盲点或自动重试。前端回归命令：在 `front/` 执行 `npm run test:platform-delivery`。

构建页面的浏览器回归：准备项目 Patchright 驱动并完成前端构建/复制后，在 `front/` 执行 `node scripts/test-platform-delivery-browser.mjs`。该测试拦截全部网络请求，使用本地模拟接口，截图输出到 `tmp/three-platform-delivery-ui/`，不访问正在运行的后端或招聘网站。

- **Boss 直聘**（[Boss.java](src/main/java/com/getjobs/worker/boss/Boss.java)）

  > 需要配置 `sayHi` 打招呼语，否则会投递失败。打招呼次数有每日上限。
  > 投递结束后会自动更新黑名单企业，回复过拒绝类消息的公司不再投递。

- **发送图片简历**

  > 将 PDF 简历转换为 `resume.jpg` 放入 `src/main/resources/`，并把配置项 `sendImgResume` 设为 `true`。
  > 任何 PDF 转图片工具都可以，图片分辨率建议控制在一屏以内。

- **猎聘**（[Liepin.java](src/main/java/com/getjobs/worker/liepin/Liepin.java)）

  > 需在猎聘 App 最新版中设置打招呼语（默认或自定义均可）。
  > 只支持微信扫码登录，需先绑定微信账号。

- **51job**（[Job51.java](src/main/java/com/getjobs/worker/job51/Job51.java)）

  > 投递有次数上限，且搜索结果中有效岗位较少，建议小范围试跑。

- **智联招聘**（[ZhiLian.java](src/main/java/com/getjobs/worker/zhilian/ZhiLian.java)）

  > 需指定默认投递的简历类型（在线简历或附件简历），否则会投递失败。
  > 只支持微信扫码登录。
